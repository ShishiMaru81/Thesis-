## Example responses (same missing-field-size question)

Row `08854472` (subtype `missing_area`, English). Only one frontier model was run, so one model is shown, in both arms. Verbatim API output (visible answer only).

**Question:**

```text
My Mango field is at the mid-season stage. Today ET0 is 5.3 mm and it rained 1.07 mm. How many liters of irrigation water does it need today?
```

**gpt-oss-120b ZS** (class `answer`, clarify exact = 0, visible tokens 449, reasoning tokens 161):

```text
**Step‑by‑step calculation**

| Parameter | Value | Unit |
|-----------|-------|------|
| Reference evapotranspiration (ET₀) | 5.3 | mm day⁻¹ |
| Rainfall (P) | 1.07 | mm day⁻¹ |
| Crop coefficient for mango (mid‑season) | **Kc ≈ 0.85** | – |
| Area for the conversion (standard) | 1 ha | – |
| 1 mm of water on 1 ha = 10 000 L | – | – |

1. **Crop evapotranspiration (ETc)**  
   \[
   ET_c = ET_0 \times Kc = 5.3 \times 0.85 = 4.505\ \text{mm day}^{-1}
   \]

2. **Net water requirement after accounting for rainfall**  
   \[
   \text{Net water needed} = ET_c - P = 4.505 - 1.07 = 3.435\ \text{mm day}^{-1}
   \]

3. **Convert the net depth (mm) to volume (liters) for 1 ha**  
   \[
   1\ \text{mm on 1 ha} = 10\,000\ \text{L}
   \]  
   \[
   \text{Irrigation water needed} = 3.435\ \text{mm} \times 10\,000\ \frac{\text{L}}{\text{mm·ha}} = 34\,350\ \text{L ha}^{-1}
   \]

---

### Answer
**The mango orchard (mid‑season) requires about 34 350 L of irrigation water per hectare today** (after subtracting the 1.07 mm of rainfall).  

If you are irrigating a different area, simply scale the volume proportionally (e.g., 0.5 ha → ≈ 17 175 L).
```

**gpt-oss-120b ZS+P** (class `clarify`, clarify exact = 1, visible tokens 55, reasoning tokens 74):

মোট পানির পরিমাণ হিসাব করতে জমির মাপ জানতে হবে। অনুগ্রহ করে জানান: একর, শতক, বিঘা, হেক্টর, নাকি বর্গমিটার?

## Issues noticed

1. **Response language under prompt P.** Excluding the 40 code-switched rows, gpt-oss ZS+P answered 7/124 English questions mainly in Bengali script and 42/124 Bengali questions mainly in non-Bengali script (ZS: 0/124 and 1/124; `s8_part_a.is_bengali_script`, ≥ 50% Bengali letters). Under prompt P it appears to answer in the language of the matching few-shot example, not the language of the question. Scoring was not changed.
2. **Clarify exact vs class.** For gpt-oss ZS, clarify exact = 6/68 but learned clarification (class `clarify`) = 1/68: some responses name the missing input and still compute an answer with an assumed value. The registered rule counts them as clarify exact; Table A reports both invented and clarify exact, so they show up in both columns.
3. **Long zero-shot answers.** 66.0% of gpt-oss ZS responses exceed 512 visible tokens (none truncated by the API). Out-of-scope ZS answers often invent specific products and prices instead of abstaining. The Llama arms were generated with a 512-token cap, so the primary CE comparison (F4) is length-asymmetric; see the 512-cap columns.
4. **Not bit-reproducible.** temperature 0 and seed 42 were sent, but system_fingerprint took 47 distinct values over 576 requests, so reruns may differ.
5. **Temperature.** Groq's model page suggests temperature 0.5–0.7 for gpt-oss; 0 was kept as registered (amendment 2). No responses ended with finish_reason `length`.
6. **Llama tokenizer source.** Llama truncation (≥ 511 tokens) uses the tokenizer saved with the local adapter (`v3/models/s5/llama31_8b_seed42/final_adapter`), because the gated meta-llama repository is not cached. It reproduces the Stage 8 values exactly (`scores/reference_check.csv`).
7. **Free-tier token window.** The largest rolling-24 h sum of API-reported total tokens in the cache is 201,190 (limit 200,000; a response's token count is only known after the call). No request was rejected for the daily token limit; the 4 `daily_limit` entries in `failures.jsonl` are the throttle's own clean stops.
8. **Bengali hedge phrases** (registered list, 34 bn clarify rows): responses containing any listed phrase, summed over phrases: {'gptoss_ZS': 13, 'gptoss_ZS+P': 4}. Details in `scores/hedge_phrases.csv`.

## Limitations

- One frontier model, one run, one prompt P; results may not generalise to other commercial models.
- Reasoning: reasoning_effort was set to low (the lowest level Groq supports for gpt-oss-120b). Unlike the planned Gemini model, the API reported reasoning tokens (576/576 responses) and returned the reasoning text, so hidden reasoning did occur. It is excluded from the 512-visible-token rule and is not scored.
- For the excluded Gemini dry-run responses only: the thinking level was set to low and the API reported no thinking tokens, so it is unknown whether hidden reasoning occurred.
- The hard out-of-domain rows have gold answers pending human review; only abstention is scored on them.
- CE(b) depends on a registered marker list; the human assumption audit is pending.
